Chap22: OOP — Core Principles
*****************************
	* Name Mangling - Name mangling is Python's mechanism for handling attributes/methods whose names start with two underscores (__).
	  In python, if we try to access private variable, it will give error like attributeError. What python does internally, it changes the name to 
		__salary
			↓
		_Employee__salary
		
		Now we can access it emp._Employee__salary . This is called Name mangling.
	  Purpose : Mainly to avoid accidental name collisions in inheritance, not to provide true security. 
	  *** Name mangling applies to methods too
	
	* Method Overloading - Python does not support traditional method overloading like Java. The key reason is that Python treats a function/method name as a single name in a class namespace. It doesn't maintain multiple versions of the same method based on parameter count/types like Java does.
		** Python doesn't support traditional method overloading because defining a method with the same name again replaces the previous definition in the class namespace. Since Python is dynamically typed, it instead commonly uses default arguments, *args, **kwargs, or runtime dispatch to achieve similar behavior.

	* MRO (Method resolution order), its like (<class '__main__.Employee1'>, <class '__main__.Employee'>, <class 'abc.ABC'>, <class 'object'>)
	  Why MRO gives Object at the end? Every normal Python class ultimately inherits from object. Think of object as the root/base class. Because object provides fundamental behavior that all Python objects have, such as methods related to: all dunder functionalities.
	  
	* Diamond problem
		       A
			  / \
			 B   C
			  \ /
			   D
	When D calls show(), should Python use B → A or C → A? Python solves this using MRO + C3 linearization. It follows linear approach, D → B → C → A → object
	* Deep meaning of Super() - super() means: Continue method lookup according to the MRO from the current class. super() does not have to be the first line of a method. It can be used at any point where you need to call the next implementation in the MRO.

	* Why does an iterator have __iter__() too?
		We might think: 
			"If an iterator already gives me values using next(), why does it need __iter__()?" - Python's iterator protocol requires an iterator to return itself from __iter__().
			
	*   | Feature               | Iterable          | Iterator       |
		| --------------------- | ----------------- | -------------- |
		| Can be used in `for`  | ✅                 | ✅              |
		| Has `__iter__()`      | ✅                 | ✅              |
		| Has `__next__()`      | Usually ❌         | ✅              |
		| Keeps iteration state | Usually ❌         | ✅              |
		| `iter(obj)`           | Produces iterator | Returns itself |
		| `next(obj)`           | Usually ❌         | ✅              |

Chap26. Generators 
******************
	* A generator is a lazy iterator that uses yield to produce a value, pause execution, remember its state, and resume later. It is having 2 methods yield and next. Yield means will return value and then pause the executio, and remembers its state.
	* return vs yield
		return - Once return executes, the function is finished.
		yield - The function doesn't finish permanently when it reaches yield. It pauses.
		
	* How does generator remeberes state?
		Python remembers:
			local variables
			current execution position
			function state
		Python doesn't restart the function. It pauses and later resumes.
		
	* Generator is an Iterator. As iter(g) is g only. so Therefore, a generator implements the iterator protocol: __iter__ and __next__
	** yield returns one value/object; yield from returns each value from another iterable/iterator one by one. 
	   yield = give me the inside box 📦; yield from = give me what's inside the box.
	   
	* for loop and Generator - Python does automatically next() call and at the end, it fires StopIteration() call.
	* Purpose of generator - “The main purpose of a generator is to produce values lazily, one at a time, using yield, instead of storing all values in memory at once. This makes generators memory-efficient and useful for large datasets, file processing, streams, and infinite sequences.”
	
	* List comprehension vs generator expression : All are same but for list, need to enclosed in [] but for generator, its enclosed in ()
	* During compilation, When Python reads this function definition, it sees the yield keyword and marks outer as a generator function.
		x=generator() # It creates a generator object.
		
	** we can check the type of object whether its iterator or generator. To get the inner generator , next(outer generator) will give inner generator.
