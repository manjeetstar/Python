Chap27:  Lambda Functions
*************************
	* A lambda function is a small, anonymous function written in a single expression.
		lambda arguments: expression
		The lambda itself creates a function object.
		
	* Lambda vs Normal function
			def                    lambda
			 │                       │
			 ▼                       ▼
			named function          anonymous function
			multiple statements     single expression
			explicit return         implicit return
			
	* Lambda functions can have default arguments. greet = lambda name="Manjeet": f"Hello {name}"
	
	* Lambda with all if..else
	
	* Lambda with Map - map(lambda function, iterables)
		numbers = [1, 2, 3, 4, 5]
		result = map(lambda x: x * x, numbers)
		
	* Lambda with sorted 
			sorted(iterable, key=lambda item: sorting_value)
			
			students = [
				("John", 85),
				("Alice", 92),
				("Bob", 78)
			]
			result = sorted(students, key=lambda x: x[1]) // Here x[1] means sorting based on age.
		For changing the order, result = sorted(numbers, key=lambda x: x, reverse=True)
		
	* Lambda With reduce() - reduce(function, iterable, initializer)
		result = reduce(lambda a, b: a + b, numbers)
		
	* Lambda Inside Another Function - We can return Lambda expression too from a function as well. While calling the function, it returns a lambda expression with held value(even outer function has finished). This is what we call it closure.
	
	* Immediately Invoked Lambda - result = (lambda x: x * x)(5) Here (lambda x: x * x) creates a function expression and (5) is the argument passed to the function.
	* Lambda Limitations
		- You cannot have multiple statements
		- You cannot write normal control-flow blocks
	
	** Lambda in Real Automation/API Testing Here Sorted, min, max so we need to use it as much required.
	   Max : max(data, key=lambda x: x["score"])
	   Min : min(data, key=lambda x: x["score"])
	
	* A higher-order function is a function that:
		1. accepts another function as an argument, or
		2. returns another function. Here in function, we are sending a lambda expression.
		
Chap28:  Functional Programming
*******************************
	* Functional Programming (FP) is a programming style where computation is expressed by applying functions to data, while trying to minimize changing state and side effects.
	
	* We can filter, map and reduce all in a single statement , this is what called functional programming, applying functions on data.
		ages=[10,3,45,32,24]
		result=reduce(lambda a, b: a+b, list(map(lambda y: y*2, filter(lambda x: x%2 == 0, ages))), 0)
		print(result)

	* First-Class Functions - Python treats function as first class function whether it can assigned to a variable or passed as an argument or returned from another function(returning lambda expression)
	
	* A pure function:
		1. Always produces the same output for the same input.
		2. Doesn't modify external state.
	  Impure function
		External state
			 ↑
			 │
		function modifies it
	* A side effect occurs when a function does something beyond calculating and returning a value. like inserting in database or writing in file or hitting any api endpoint etc..
	
	** Function Composition : its like f(g(x) where g is a function and f is a function too. Output of g becomes input of f.
	   we can create our own..
			def compose(f, g):
              return lambda x: f(g(x))
			  
			double = lambda x: x * 2
			square = lambda x: x * x

			operation = compose(square, double)

			print(operation(5))
			
	* Referential Transparency - An expression is referentially transparent when you can replace it with its result without changing program behavior.
	* Functions as Data : data → function → result. Its like in the place of data, we are passing the function expression
			operations = [
				lambda x: x + 10,
				lambda x: x * 2,
				lambda x: x ** 2
			]
			
	* functools — Important Module
		functools.reduce()
		functools.partial()
		functools.lru_cache()
		functools.cache()
		functools.wraps()
		
	** Functional Programming Principles
			1. First-class functions
			2. Higher-order functions
			3. Pure functions
			4. Minimize side effects
			5. Prefer immutability
			6. Function composition
			7. Declarative thinking
			
Chap29: Decorators
******************
	* A decorator is a function that modifies or extends the behavior of another function without changing its source code.
	* Decorator can be used for Logging, Authentication,Authorization,Timing,Retry,Caching,Validation,Metrics,Tracing,Exception handling
	* Decorators depend heavily on the fact that Python functions are objects. You can assign a function to a variable.
	* Pattern of a decorator
			decorator
			   │
			   ├── receives function
			   │
			   └── returns wrapper
						 │
						 ├── before
						 ├── original function
						 └── after
	*  @wraps(func) This is we need to tagged to wrapper method. This is just to save meta data associated with original function, not the wrapper function.
	if we dont do, then print(<original_Method>.__name__) will return wrapper... Other than __name__, other meta data __doc__ and __module__
	 
	* If decorator function has a parameter then the sequence would be like..
			retry()
			   ↓
			decorator()
			   ↓
			wrapper()
			   ↓
			original function
			
		Here we need to return result, followed by wrapper and decorator. Why? Because its a decorator factory so it returns that manyy decorator.
	* we can tag multiple decorator to a function.
		@decorator1
		@decorator2
		def process(): # Here execution order would decorator1 first, followed by decorator2.
		
		process = decorator1(decorator2(process))
		Here output would be
			decorator1 before
			decorator2 before
			TEST
			decorator2 after
			decorator1 after
			
	** Decorator with class : We can define decorator within a class and that can be applied to a method.
	Class-based decorator — __call__ needed, we need to implement within class. __call__ makes an object behave like a function.
		class Log:
		def __init__(self, func):
			self.func = func

		def __call__(self, *args, **kwargs):
			print("Before")
			return self.func(*args, **kwargs)
			
		Then
			@Log
			def calculate(a, b):
				return a + b
		calculate(10,20)
		
		Class decorators are useful for:
			- registration
			- dependency injection
			- configuration
			- metadata
			- plugin systems
			
Chap30: Closures
****************
	-  A closure is a function that remembers and can access variables from its enclosing (outer) function even after the outer function has finished executing.
		** Nested function + reference to an enclosing variable + that function survives/escapes the enclosing scope = closure.
		
	-  why and how does it happen? - This connects directly to Python's scope and object lifetime. Even outer function has finished execution but inner function has reference to outer variable. So its still pointing to the variable. Means variable is still reachable to inner function so its didnt garbage collected.
	- __closure__ : Python actually exposes closure information.
	  For insepcting the actual value, print(func.__closure__[0].cell_contents)
	 
	- Each Closure Has Its Own State. It means if we are calling function which return inner function twice and assigned to  two different variable then for both the variable, which will hold inner function, will have its own closure state.
	
	- Closures Can Maintain Mutable State. Means they can modify outer variable too by declaring it as nonLocal.
	
	- def counter():
			count = 0
			def increment():
				count += 1 // pt5
				return count
			return increment
	  Here it will give nonLocalError. because pt5 is basically an assignment and it looks for local variable.  but there is no count local variable.
	  nonlocal tells Python: "Don't create a new local count. Modify the count belonging to the enclosing function."
	  
	  -- global   → module/global scope
		 nonlocal → nearest enclosing function scope
		 
	- Closure vs Class : Here state means data
		Class
		 └── object
			  └── state

		Closure
		 └── function
			  └── captured state
	    A class is generally better when you have multiple operations/state fields. A closure can be elegant when you need a small private stateful function.
		
	- Classic Closure Loop Problem : 
			def create_functions():
				functions = []
				for i in range(3):
					def func():
						return i
					functions.append(func)
			    return functions
				
		    functions = create_functions()
			for f in functions:
				print(f()) // Here function will not return 0,1,2 but it will return 2,2,2. Because the functions don't capture the value of i at each iteration. They capture the variable i. By the end of execution, the value is 2 so it will return 2 only.
				
	    How to fix it? In inner function signature , if we do like func(i=i) It means Python concept: default arguments are evaluated when the function is created, not when it is called. the right-hand i is evaluated immediately and stored as the function's default value. So its like...
			function[0] → default i = 0
			function[1] → default i = 1
			function[2] → default i = 2
			
	- How Python Resolves Variables: LEGB? That enclosing lookup is what makes closures possible. Means if local is not present, will look enclosing , then global and finally built-in.
	
	- How default arguments are evaluated? - the default argument is not a closure variable. i=i in def func(i=i) is capturing the current value as a default argument; it is not creating a closure.
	
Chap31:  Context Managers
*************************
	* A context manager guarantees that something is properly set up before a block runs and properly cleaned up after the block finishes.
	- Without the context manager, We have to remember:
			Open the resource
			Use the resource
			Close the resource
			Make sure it closes even if an exception occurs
	- Context Manager works in this fashion...
			ENTER
			  ↓
			resource acquired
			  ↓
			execute with block
			  ↓
			EXIT
			  ↓
			resource cleaned up
			
	- Internally what happens? When Python sees:
		with something as x:
			...
	    it looks for two special methods: __enter__ and __exit__ dunder methods. So a context manager essentially provides: __enter__ for setup and __exit__ for cleanup activities.
		Signature of both methods
			 def __enter__(self):
			 def __exit__(self, exc_type, exc_value, traceback):
			 
	- For context managers, we very commonly need try/finally without except. Exception is being handled by __exit__ only.
	  __exit__() is responsible for cleanup. It receives three arguments: def __exit__(self, exc_type, exc_value, traceback). They describe an exception, if one occurred. If no exception, then all three arguments will be having None value.
	  In case of exception, 
			with MyContext():
				raise ValueError("Oops") Here exc_type is ValueError, exc_value is oops and traceback is traceback informations.
		
		**** __exit__() runs even when an exception occurs		
		**** Can __exit__() suppress an exception? YES. if __exit__ returns true, exception will be suppressed.
		
	- When we write -- Here MyContext is a class having __enter__ and __exit__ methods implementation.
		with MyContext():
			do_something()
		
		Internally, its being transpiled to ...
		
			context = MyContext()
			value = context.__enter__()
			try:
				do_something()
			finally:
				context.__exit__(None, None, None)
				
		But the actual exception handling is more nuanced because Python passes exception information to __exit__().
		
	- Context Manager with a Lock:			
			acquire lock
				 ↓
			run code
				 ↓
			release lock
			
	- We can have multiple context manager together in a single line. __enter__() and __exit__() are not inherently "database methods" or "file methods." They are part of Python's context manager protocol. They can be implemented by any object/class that wants to participate in.
	
	- contextlib : Just to avoiding writing boilerplate code like for __enter__ and __exit__ method, python provides a module contextlib specifically for context manager...
		For context managers, we very commonly need try/finally without except. Exception is being handled by __exit__ only.
		
			@contextmanager
			def dbManagement():   				
				try: 
					yield "Manjeet", "Singh"
				finally:    
					print("Performed cleanup activities")

			with dbManagement() as (a, b):
				print(f"Returned outcomes {a} {b}")
				raise ValueError("This is the error")
