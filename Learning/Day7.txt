Chap40. Shallow Copy vs Deep Copy 
*********************************
	* Shallow copy creates a new outer object but shares nested objects; deep copy recursively creates independent copies of nested objects.
	* Assignment vs Shallow copy vs Deep copy
			Assignment
				↓
			same object

			Shallow Copy
				↓
			new outer object
			same nested objects

			Deep Copy
				↓
			new outer object
			new nested objects
			
	* Shallow Copy - Copies only outer and not nested one.
			original ─────► Outer List A
                  │
                  ├──► List X [1,2]
                  │
                  └──► List Y [3,4]


			shallow ──────► Outer List B
							  │
							  ├──► List X [1,2]
							  │
							  └──► List Y [3,4]
							  
	  Deep copy - Deep copy recursively copies the objects inside.
			original ─────► Outer List A
                  │
                  ├──► List X [1,2]
                  └──► List Y [3,4]


			deep ─────────► Outer List B
							  │
							  ├──► List P [1,2]
							  └──► List Q [3,4]
							  
	* Why deep copy can be expensive??
		deepcopy() recursively walks the object graph and creates independent copies. Shallow copy is cheap.
		
	** In shallow copy, a=[1,2,[11,1,2,2]] b=a.copy() Now a[0] is b[0] shouuld be false... I can understand nested will refer the same. does it mean from the same list?
		After Shallow copying,
			a                              b
			┌─────┬─────┬─────────┐       ┌─────┬─────┬─────────┐
			│  ───┼─►1  │  ───────┼─►     │  ───┼─►1  │  ───────┼─►
			└─────┴─────┴─────────┘       └─────┴─────┴─────────┘
		The slots are different, but the references stored in those slots can point to the same object. Thats why it will be true only.
		
		For deepcopy, Same will happen but only for immutable objects. This is the key distinction.
		
Chap41. Python Import System 
****************************
	* Python catches all the imported modules in sys.modules. we can remove a module from the cache like del sys.modules("Math")
	* Adding our own directory to sys.path like sys.path.append(<Path>). After this, Python may search imported folder in this supplied path.
	*** Each module gets a special attribute called __name__. if you print in a file, it returns value __main__
	  thats why when we write if __name__ == __main__ : <Execute following code. That means if we run the current file then only followed code under if, will be executed.
	  
	  while importing, in that file, it becomes __name__ == module_name
			Executed directly
				  ↓
			__name__ == "__main__"

			Imported
				  ↓
			__name__ == module name
			
	***	 python tools/cleanup.py
			└────── file path

		 python -m tools.cleanup
			└──── module path
			
	*** Circular import
				import a
				   │
				   ▼
				Create module object
				   │
				   ▼
				Put module in sys.modules
				   │
				   ▼
				Execute a.py
				   │
				   ├── imports b
				   │      │
				   │      ▼
				   │   execute b.py
				   │      │
				   │      └── imports a
				   │              │
				   │              ▼
				   │       a already exists in sys.modules
				   │       BUT a is not finished executing
				   │
				   ▼
				a is eventually completed
				In this case, python will give partially initialized module error.
				
		Fixes: 
			1. Move shared functionality into another module. Create a common module.
			2. Local import - means import within the function. This is a local import. The import occurs when the function executes rather than when the module initially loads.
			3. importlib - Python provides the importlib module for programmatic importing. we can dynamically import module.
				import importlib
				math_module = importlib.import_module("math")
			4. Dynamic imports - Same as pt 3

Chap42. Virtual Environments & Dependency Management 
****************************************************
	* why do we prefer Virtual env as to solve "How do we make sure Project A and Project B can use different Python packages and versions without interfering with each other?"
	* A virtual environment creates an isolated Python environment for a project.
		python -m venv .venv [This is .venv creation command ]
			python
			  ↓
			find venv module
			  ↓
			execute venv
			  ↓
			create .venv
			
		Inside .venv - We can see /bin, /include, /lib, /lib64 folders and .gitignore and pyvenv.cfg files.		
		Activating the virtual environment - in wsl(linux), source .venv/bin/activate , Activation mainly changes your shell's environment so that commands such as: pip, requests resolve to the virtual environment's executables.
		In layman terms
			Before activation
				python
				  ↓
				Global Python

			After activation
				python
				  ↓
				.venv Python
	
	* Checking which libraries are installed, pip list
	  pip freeze means: Show all Python packages currently installed in the active Python environment, along with their exact versions.
	  pip check : This checks whether installed packages have compatible dependencies.
	  pip install --upgrade requests : for updating to latest packages.
	  pip uninstall requests
	  
	* python -m pip install requests - Means it ties pip to the selected Python interpreter. But pip install requests could install into Python 3.10 while your application runs with Python 3.12.
		System Python
			/home/user/.local/bin/python
		Virtual environment
			/home/user/project/.venv/bin/python
	** python -c "import sys; print(sys.executable)" - it tells which python interpreter is executing the code.
